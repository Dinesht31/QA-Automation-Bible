#1.Explain JDK, JRE, and JVM using the kitchen analogy.

## Kitchen Analogy for JDK, JRE and JVM

Imagine I want to prepare tea in a kitchen.

**JDK (Java Development Kit)** is the complete kitchen. It contains all the utensils, gas stove, pan, kettle, water, tea leaves and other tools needed to prepare tea. Similarly, JDK contains everything required to write, compile and run Java programs.

**JRE (Java Runtime Environment)** is the ready-to-use cooking environment. Once the kitchen is arranged, JRE provides the environment required to run the Java application.

**JVM (Java Virtual Machine)** is like the gas flame that actually cooks the tea. It executes the compiled Java bytecode and makes the Java program run.
  

#2. What happens when you click Run in IntelliJ? (Write the steps in order.)

1. I write Java source code in a `.java` file.
2. IntelliJ invokes the Java compiler (`javac`).
3. The compiler checks for syntax errors.
4. The compiler converts the `.java` file into a `.class` file (bytecode).
5. JVM loads the compiled class into memory.
6. JVM executes the bytecode.
7. The Java program starts running.
 

#3. What is the difference between .java and .class files?

A `.java` file contains the Java source code written by the programmer. It is human-readable and can be edited in IntelliJ IDEA.

A `.class` file contains Java bytecode generated by the Java compiler. JVM reads this bytecode and executes the program.

#4. Why is Java called "Write Once, Run Anywhere"?

Java is called "Write Once, Run Anywhere" because the Java compiler generates platform-independent bytecode. The same bytecode can run on Windows, Linux, or macOS as long as a compatible JVM is available on that operating system.
